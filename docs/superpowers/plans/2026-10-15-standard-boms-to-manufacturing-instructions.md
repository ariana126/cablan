# Rename `standard-boms` to `manufacturing-instructions`: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use
> checkbox (`- [ ]`) syntax for tracking. In this repo, every task is carried out by the
> `backend-engineer` sub-agent. It reads `backend/CLAUDE.md` before starting.

**Goal:** Move the backend module `standard-boms` to `manufacturing-instructions` and rename its
inward-facing code from `StandardBom*` to `ManufacturingInstruction*`. Nothing a client, a stored
row or a user can observe may change.

**Architecture:** This is a mechanical rename, driven by one protected-token Perl script. The
script rewrites `StandardBom`/`standardBom` identifiers everywhere in the module **except** a fixed
list of names that are part of the public contract or stored data. Prisma models are renamed, but
every `@@map`/`@map` is kept, so the database does not change. Consuming modules (`boms`,
`audit-logging`) change only what the TypeScript compiler forces them to change.

**Tech Stack:** NestJS 11, `@nestjs/cqrs`, Prisma 7 (client generated by `postinstall` inside the
Docker image), Jest, dependency-cruiser, Docker Compose. All commands run in containers through
`make`.

**Spec:** `docs/superpowers/specs/2026-10-15-standard-boms-to-manufacturing-instructions-design.md`.
Read it before starting. Section 2 of the spec ("What deliberately stays") overrides any
instruction here that seems to contradict it.

## Global Constraints

- Only files under `backend/` and `docs/` may change. Nothing under `frontend/` or
  `acceptance-tests/` may change.
- `backend/docs/openapi.json` and `backend/docs/openapi.yaml` must be byte-identical after
  `make generate-swagger`.
- No new folder may appear under `backend/prisma/migrations/`. Generated paths are guarded by a
  hook anyway.
- Kept names, never renamed:
  - `StandardBomController`
  - `RegisterStandardBomDto`, `RegisterStandardBomComponentDto`, `RegisterStandardBomMaterialDto`
  - `UpdateStandardBomDto`, `ReportStandardBomsDto`, `StandardBomReportFiltersDto`,
    `ExportStandardBomsDto`
  - `StandardBomExportFormat`
  - `@Controller('standard-boms')`, `@ApiTags('Standard BOMs')`
  - every problem-type URI and title string
  - every exception and log message text
  - `AuditRecordType.StandardBom` and the literal `'StandardBom'`
  - `BomStandardBomNotFound`
  - `Bom`'s own `standardBomId` / `standardBomMiCode` / `standardBomMiCodes`
  - every `@@map`/`@map` value
- Kept file paths, never moved:
  - `infrastructure/http/controllers/standard-bom/**`, which holds the controller and the DTOs
  - `infrastructure/spreadsheet/standard-bom-export-grid{,.spec}.ts`
  - `boms/application/exceptions/bom-standard-bom-not-found.exception.ts`
- Final history: exactly one commit on top of the commit `HEAD` pointed at when execution
  started (recorded in `/tmp/mi-rename.base`), with the message
  `refactor(backend): rename standard-boms module to manufacturing-instructions`.
- Use `git mv` for every move so that history follows the files.

## Review Focus

These are the failure modes most likely to reach a user that no existing unit test pins down:

1. **Problem Details for MI errors.** A duplicate MI code, a missing component, a missing
   material, an unknown product or an unknown composition entry must still return the same
   `type`, `title`, `status`, `detail` and extension members. **Pinned by** the new
   `exception.mapper.spec.ts` in Task 1, written and passing **before** the rename.
2. **Audit entries for MI changes.** They must still be stored with `recordType 'StandardBom'`
   and the same change keys. **Pinned by** the existing `standard-boms-audit.handlers.spec.ts`;
   its `'StandardBom'` assertions are protected from the script.
3. **Existing database rows.** They must still be read and written exactly as before. **Pinned
   by** the schema diff in Task 3.
4. **Daily dashboard standard weights.** The dashboard must still find each product's standard
   weights. `boms`' dashboard repository queries `prisma.standardBom` directly, and that accessor
   renames with the model. **Pinned by** `tsc` and the acceptance `bom-dashboard` scenarios in
   Task 3.
5. **Stale Prisma client in running stacks.** Containers created before the rename keep the old
   generated client in their `node_modules` volume and would crash on
   `prisma.manufacturingInstruction`. **Pinned by** the image rebuild and stack recreation steps
   in Tasks 1 and 3.

- [ ] **Step 2: Write the Problem Details pinning spec (against the old names)**

Create `backend/src/modules/standard-boms/infrastructure/http/exception.mapper.spec.ts`:

```ts
import { HttpStatus } from '@nestjs/common';
import {
  StandardBomComponentMustHaveAtLeastOneMaterial,
  StandardBomCompositionEntryNotFound,
  StandardBomMiCodeAlreadyExists,
  StandardBomMustHaveAtLeastOneComponent,
  StandardBomProductNotFound,
} from '@standard-boms/application/exceptions';
import { MiCode } from '@standard-boms/domain/value/mi-code.vo';
import { StandardBomsExceptionMapper } from './exception.mapper';

// Pins the public Problem Details contract of this module's exceptions, so
// that renaming the classes behind them cannot change what a client sees.
describe('StandardBomsExceptionMapper', () => {
  const mapper = new StandardBomsExceptionMapper();

  it('maps a duplicate MI code to a 409 with the MI code', () => {
    const problem = mapper.toProblemDetail(
      StandardBomMiCodeAlreadyExists.withMiCode(MiCode.fromString('MI-1')),
    );

    expect(problem).toMatchObject({
      typeUri: 'standard-bom-mi-code-already-exists',
      title: 'Standard BOM MI Code Already Exists',
      status: HttpStatus.CONFLICT,
      detail: 'A standard BOM already exists with MI code MI-1',
      extensionMembers: { miCode: 'MI-1' },
    });
  });

  it('maps a BOM without components to a 400', () => {
    const problem = mapper.toProblemDetail(
      StandardBomMustHaveAtLeastOneComponent.create(),
    );

    expect(problem).toMatchObject({
      typeUri: 'standard-bom-must-have-at-least-one-component',
      title: 'Standard BOM Must Have At Least One Component',
      status: HttpStatus.BAD_REQUEST,
      detail: 'A standard BOM must have at least one component',
    });
  });

  it('maps a component without materials to a 400 with the component id', () => {
    const problem = mapper.toProblemDetail(
      StandardBomComponentMustHaveAtLeastOneMaterial.forComponent('c-1'),
    );

    expect(problem).toMatchObject({
      typeUri: 'standard-bom-component-must-have-at-least-one-material',
      title: 'Standard BOM Component Must Have At Least One Material',
      status: HttpStatus.BAD_REQUEST,
      detail: 'Component c-1 must have at least one material',
      extensionMembers: { componentId: 'c-1' },
    });
  });

  it('maps an unknown product to a 400 with the product id', () => {
    const problem = mapper.toProblemDetail(
      StandardBomProductNotFound.withId('p-1'),
    );

    expect(problem).toMatchObject({
      typeUri: 'standard-bom-product-not-found',
      title: 'Standard BOM Product Not Found',
      status: HttpStatus.BAD_REQUEST,
      detail: 'No product exists with id p-1',
      extensionMembers: { productId: 'p-1' },
    });
  });

  it('maps an unknown composition entry to a 400 with the entry id', () => {
    const problem = mapper.toProblemDetail(
      StandardBomCompositionEntryNotFound.forMaterial('m-1'),
    );

    expect(problem).toMatchObject({
      typeUri: 'standard-bom-composition-entry-not-found',
      title: 'Standard BOM Composition Entry Not Found',
      status: HttpStatus.BAD_REQUEST,
      detail:
        "No material with id m-1 exists in the referenced component's current materials",
      extensionMembers: { entryId: 'm-1' },
    });
  });

  it('claims exactly its own five exceptions', () => {
    expect(mapper.canMap(StandardBomMustHaveAtLeastOneComponent.create())).toBe(true);
    expect(mapper.canMap(new Error('other'))).toBe(false);
  });
});
```

- [ ] **Step 5: Write the protected-token rename script**

Create `/tmp/rename-mi.pl`, outside the repo:

```perl
#!/usr/bin/perl -pi
# Renames StandardBom* identifiers and standard-bom* import paths, except
# the tokens and paths the spec keeps. Kept text is hex-encoded first, so
# no rename rule can match inside it, then decoded at the end.
BEGIN {
  our $KEEP_ID = qr/(?<![\w])(?:StandardBomController|RegisterStandardBomDto|RegisterStandardBomComponentDto|RegisterStandardBomMaterialDto|UpdateStandardBomDto|ReportStandardBomsDto|StandardBomReportFiltersDto|ExportStandardBomsDto|StandardBomExportFormat|BomStandardBomNotFound|AuditRecordType\.StandardBom)(?![\w])|'StandardBom'/;
  our $KEEP_PATH = qr/controllers\/standard-bom|standard-bom\.controller|(?:register|update|report|export)-standard-boms?\.dto|standard-bom-export-grid|bom-standard-bom-not-found/;
}
our ($KEEP_ID, $KEEP_PATH);
s/($KEEP_ID)/"\x{1}".unpack("H*",$1)."\x{1}"/ge;
if (/from\s+'|import\(|jest\.mock\(|require\(/) {
  s/($KEEP_PATH)/"\x{1}".unpack("H*",$1)."\x{1}"/ge;
  s/standard-boms/manufacturing-instructions/g;
  s/standard-bom/manufacturing-instruction/g;
}
s/StandardBoms/ManufacturingInstructions/g;
s/StandardBom/ManufacturingInstruction/g;
s/standardBoms/manufacturingInstructions/g;
s/standardBom/manufacturingInstruction/g;
s/\x{1}([0-9a-f]+)\x{1}/pack("H*",$1)/ge;
```

Only identifiers and import paths are rewritten. Kebab-case strings that are not imports
(problem URIs, `@Controller('standard-boms')`) and prose with spaces ("standard BOM",
"Standard BOM") are left alone.
